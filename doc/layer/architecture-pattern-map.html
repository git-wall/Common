Architecture Layers — Từng tầng, từng pattern
API LAYER
Presentation / API Layer
— Điểm tiếp xúc với thế giới bên ngoài
@RestController
Controller
Điểm vào HTTP — nhận request, gọi usecase, trả response
→ gọi Facade hoặc UseCase
Input / Output Shape
DTO
Request & Response objects — tách biệt API contract với domain
RequestDTO ≠ Entity ≠ ResponseDTO
Output Transform
Presenter
Domain → ResponseDTO. Format, label, currency, i18n
→ nhận từ UseCase output
Compose Complex Response
Assembler
Ghép nhiều domain object → 1 response phức tạp
≠ Mapper (có logic ghép)
↓ Controller gọi Facade hoặc UseCase trực tiếp ↓
APP LAYER
Application Layer
— Điều phối luồng, orchestrate usecase
Simplify Complex API
Facade
Gom nhiều UseCase → 1 interface đơn giản cho Controller
→ gọi N UseCase theo thứ tự
1 Action = 1 UseCase
UseCase
Một business action. Transaction, event publish, auth check
→ gọi Domain + Repository
CQRS
Command / Query
Tách read/write intent. Command → state change. Query → read only
DTO → Command/Query → UseCase
Async / Decoupling
Event
UseCase publish → nhiều handler react độc lập. Loose coupling
@EventListener / Kafka Consumer
Kafka / RabbitMQ
Messaging
Producer → Broker → Consumer. Async, scalable, decoupled
Outbox Pattern phòng dual-write
↓ Application gọi Domain qua Port / Interface ↓
DOMAIN
Domain Layer
— Lõi nghiệp vụ, không phụ thuộc framework
Business Identity + Rule
Entity / Aggregate
Lõi domain. Tự enforce rule. Không biết DB, không biết HTTP
→ chứa business rule thuần túy
Cross-Entity Logic
Domain Service
Logic cần nhiều Entity. Không có I/O. Không phụ thuộc infra
≠ Application Service (không có I/O)
Port (Interface)
Repository Port
Interface ở Domain, implement ở Infra. Dependency Inversion
Domain → Port ← Infrastructure
Immutable + Self-validating
Value Object
Money, Email, Address. Immutable, validate trong constructor
record / final class — no ID
Algorithm as Object
Strategy
Swap algorithm/rule runtime. Pricing, discount, tax, routing
Map<Type, Strategy> → runtime select
Complex Object Creation
Factory
Tạo Domain Object phức tạp. Đảm bảo valid state khi khởi tạo
Order.create() hoặc OrderFactory
↓ Repository Port → Implementation ở Infra ↓
INFRA
Infrastructure Layer
— Kết nối thế giới bên ngoài: DB, API, Queue
Port Implementation
Adapter
Implement Domain Port. Bridge giữa domain và external system
Inbound (REST/MQ) · Outbound (DB/API)
Field-to-Field Transform
Mapper
Domain ↔ JPA Entity ↔ DTO. Thuần field mapping, dùng MapStruct
≠ Assembler (không có logic ghép)
External Model Protection
ACL
Chặn model của external system leak vào domain. Translation layer
External model ≠ Domain model
Request Scope State
Context
userId, tenantId, correlationId. ThreadLocal. MDC logging
Filter → set → UseCase → get → clear
Cross-Cutting Concerns — Xuyên suốt mọi tầng
⚡ CROSS-CUTTING — áp dụng ở mọi layer
@Aspect / Wrapper
Decorator
Thêm logging, caching, retry vào bất kỳ component nào
AOP @Around hoặc wrapper class
Trace / Log Context
MDC / Tracing
CorrelationId xuyên suốt. MDC cho logging. OpenTelemetry
Filter → MDC.put → auto-clear
@ControllerAdvice
Exception Handler
Bắt exception toàn cục. Domain → 4xx. Technical → 5xx
Domain Exception → HTTP Status mapping
3-Layer Validation
Validator
DTO (format) → UseCase (business) → Domain (invariant)
@Valid + custom + domain rule
@Cacheable / Redis
Cache
@Cacheable trên UseCase. Redis distributed cache. Evict on change
Read-through / Write-through / Evict
Decision Guide — Nhìn tình huống → biết dùng gì
KHI NÀO DÙNG FACADE vs USECASE?
→ UseCase khi:
1 action rõ ràng, 1 transaction
Controller gọi trực tiếp

→ Facade khi:
Cần gọi nhiều UseCase theo thứ tự
Controller quá phức tạp
Cần hide complexity của application logic
PRESENTER vs ASSEMBLER vs MAPPER?
→ Mapper:
Field-to-field thuần túy (MapStruct)

→ Presenter:
Format cho display (currency, date, label)

→ Assembler:
Ghép nhiều object → 1 response phức tạp
ADAPTER vs ACL?
→ Adapter:
Implement Port interface từ domain
JPA Repository, HTTP Client

→ ACL:
Chặn external model leak vào domain
Thường wrap Adapter
Stripe → Payment, ShipStation → Shipment
EVENT vs MESSAGING?
→ Domain Event:
In-process, same transaction
Spring ApplicationEventPublisher

→ Integration Event / Messaging:
Cross-service, async
Kafka / RabbitMQ
Dùng Outbox Pattern để đảm bảo delivery
STRATEGY vs FACTORY?
→ Strategy:
Chọn algorithm lúc runtime
Pricing, Discount, Tax, Routing

→ Factory:
Tạo object phức tạp
Ẩn construction logic
Đảm bảo valid state từ đầu
DECORATOR VÀ AOP?
→ Decorator class:
Explicit, testable, compile-time visible
Tốt khi cần 1-2 UseCase cụ thể

→ AOP @Aspect:
Apply cross-cutting globally
Logging, Audit, Retry, Transaction
@Around pointcut
